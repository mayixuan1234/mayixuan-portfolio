01 · 毕业设计
基于知识图谱与通义千问 API 的医疗问答系统
⭐ 获评优秀毕设 · 点我看证书 2025.10 – 2026.05
🎬 查看演示视频（飞咔）

针对通用大模型在医疗场景的"幻觉"问题，独立设计并实现图谱增强型 RAG 问答系统。用 Python 从 Huatuo-26M 数据集抽取实体关系，构建 50 万+ 实体、125 万+ 关系边的医疗知识图谱，以 MySQL 轻量化存储替代 Neo4j；按"图谱检索 → 结构化 Prompt → 通义千问生成"链路抑制幻觉。支持文本+图片多模态问答、ECharts 图谱可视化（BFS 最短路径）。Spring Boot + Vue3 全栈实现，70 个测试用例全过。

⚠️ 浏览器渲染限制：ECharts 在 DOM 中渲染约 1000 节点即出现卡顿，实际入库可视化仅展示 713 节点 / 1857 边的可达子图；全量图谱存于 MySQL，后续计划迁移 WebGL 渲染以支持更大规模。

展开技术细节
  • 数据构建：从 Huatuo-26M 问答语料用规则 + LLM 抽取症状 / 疾病 / 药品 / 检查实体及关系，清洗去重后入 MySQL。
  • 检索与生成：以问题为起点做 BFS 子图召回（限定层数与节点数），拼入结构化 Prompt，调用通义千问生成，抑制通用大模型幻觉。
  • 多模态：支持文本 + 图片混合输入，图片经 OCR 识别后并入问答上下文。
  • 性能与测试：JMeter 100 并发压测 602.3 req/s、错误率 0%；JUnit 70 个测试用例全部通过。
  • 工程取舍：不引入 Neo4j，用 MySQL 邻接表存图谱，降低部署成本；前端仅渲染 713 节点子图以规避 DOM 渲染上限。
02 · 实践学期作品
基于 Vector RAG 的智能医疗问答助手
作品展二等奖 · 点我看证书2025.07 – 2025.10
🎬 查看演示视频（飞咔）

实践学期独立作品。从 Huatuo26M 数据集清洗出约 18 万条医患问答对、切块为 183 万文本片段，用 text2vec-base-chinese 编码为 384 维向量、建 FAISS 索引（GPU 加速）实现毫秒级检索，融合通义千问 API 流式输出。基于 Gradio 做「医疗咨询 / 用药管理 / 健康档案 / 对话历史」四模块，提示词约束模型按症状分析、用药指导等 7 个结构化模块输出，规避幻觉。

展开技术细节
  • 数据：Huatuo26M（约 18 万医患问答对）清洗为 JSONL，切块生成约 183 万规范片段。
  • 向量化：text2vec-base-chinese → 384 维向量，FAISS 建索引并启用 GPU 加速。
  • 生成：Top-K 检索 + 历史对话拼入结构化 Prompt → 通义千问 API 流式逐字输出。
  • 功能闭环：用药方案正则提取（90% 准确率）、健康档案、按日期回溯对话，JSON 本地持久化。
  • 工程取舍：本地显存不足以微调大模型，改用「向量检索 + API」零训练成本方案。
